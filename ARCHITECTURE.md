# Architecture

Personal site of Davi Lacerda (AI Engineer). Bilingual (`en`, `pt-br`), light/dark,
statically generated, deployed on Vercel. Read this before adding pages.

**Stack:** Next.js 16 (App Router, Turbopack, `proxy.ts`), React 19, TypeScript 6 (strict +
`noUncheckedIndexedAccess`), Tailwind CSS v4 (CSS-first config), next-themes, Motion
(`motion/react`), Phosphor icons, Iconify brand logos (inlined at build time),
unified/remark/rehype + Shiki for Markdown, @vercel/analytics. Package manager: **yarn** (v1).

Next 16 differs from older versions: check `node_modules/next/dist/docs/` before using an API
(`params` are Promises, `middleware` is now `proxy`, `next lint` is gone).

```bash
yarn dev          # http://localhost:3000 (redirects to /en or /pt-br)
yarn build        # production build (also type-checks)
yarn lint         # eslint . (flat config: next core-web-vitals + typescript + prettier)
yarn typecheck    # tsc --noEmit
yarn format       # prettier --write . (with the Tailwind class sorter)
yarn logos        # regenerate src/lib/logos/icons.json after editing the logo registry
yarn brand        # regenerate the favicons, app icons and public/brand/logo.svg from the mark
```

## Routing and i18n

- Every page lives under `src/app/[lang]/`. `[lang]/layout.tsx` is the root layout (there is no
  `app/layout.tsx`). Root-level route handlers/metadata routes (`app/robots.ts`, `app/sitemap.ts`,
  `app/llms.txt/route.ts`, `app/manifest.ts`) are fine without a layout.
- `src/proxy.ts` redirects any path without a locale (`/`, `/personal`) to `/<locale>/...` and fixes
  wrong casing (`/pt-BR` -> `/pt-br`). It skips `_next/`, `api/`, any path with a dot
  (`robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`, `rss.xml`, `manifest.webmanifest`,
  images) and `opengraph-image` / `twitter-image` / `icon` / `apple-icon`.
- `@/i18n`:
  - `locales = ["en", "pt-br"]`, `type Locale`, `defaultLocale = "en"`, `isLocale()` (type guard for params)
  - `localeMeta[lang]` -> `{ htmlLang: "pt-BR", hreflang, ogLocale: "pt_BR", intl, label, short }`
  - `getDictionary(lang)` (sync) -> typed UI strings. `en.ts` defines the shape (`Dictionary`);
    `pt-br.ts` must match it. **Add new keys to both files.**
  - `t(value, lang)` resolves an `L10n` (`{ en, "pt-br" }`) or passes a plain string through.
  - `interpolate("{minutes} min read", { minutes: 4 })`.
- `@/i18n/format`: `formatDate("2026-10-24", lang, "long" | "short")`, `formatPartialDate("2024-08", lang)`
  -> "Aug 2024", `formatLongPartialDate()` -> "August 2024", `formatDateRange(start, end, lang)` ->
  "Dec 2023 to Aug 2024" or, with `end: null`, "Since Aug 2024" (no dashes in visible text),
  `toIsoDate()` for `<time dateTime>`. All UTC.
- `@/lib/routes`: `routes.work(lang)` `/en`, `routes.topic(lang, "experience")` `/en/work/experience`,
  `routes.ask(lang)` `/en/ask`, `routes.personal(lang)`, `routes.blog(lang)`
  (`/en/personal#blog`, so give the blog section `id="blog"`), `routes.post(lang, slug)`,
  `routes.rss(lang)` (`/en/personal/blog/rss.xml`), plus `tabs`, `activeTab()`, `switchLocalePath()`.
- Locale switcher: swaps the prefix by default. Pages whose URL differs per locale (blog posts)
  render `<LocaleAlternates links={getPostAlternates(post)} />` (client, renders nothing). It also
  sets a `NEXT_LOCALE` cookie the proxy honours.

## Design system

Monochrome, clean and direct. White and near-black with a disciplined grey ramp; hierarchy comes
from type weight, size and space only. The only colour on the site is a brand's own logo (team and
game logos and Valorant's rank emblems included), the album cover on the Spotify tile and the
show's poster. No self-referential copy (nothing about how the site works or that answers are pre-written): the page
says what Davi did, in as few words as possible. The long versions live in the machine-readable
layer (see Agent readiness). The Work tab is a split-pane assistant whose answers are pictures
first (oversized figures, big logo marks, an ink panel for the headline fact); Personal is a bento
grid of surface tiles over a reading layout, and the blog is a reading layout. Tokens are CSS variables in `src/app/globals.css` (`:root` = light,
`.dark` = dark; next-themes toggles the class, system preference by default) mapped to Tailwind
colors:

| Utility (`bg-*`, `text-*`)  | Light (dark)      | Use                                                           |
| --------------------------- | ----------------- | ------------------------------------------------------------- |
| `background` / `foreground` | #ffffff / #0a0a0a | page and body text (dark: #000000 / #ededed)                  |
| `surface`                   | #f4f4f4 (#181818) | panels, the composer, chips, tags, logo tiles, code           |
| `surface-strong`            | #e8e8e8 (#272727) | hover on a surface, past jobs on the timeline                 |
| `muted-foreground`          | #666666 (#a1a1a1) | secondary lines only (>= 5.2:1 on page and surface)           |
| `border`                    | #dcdcdc (#313131) | form fields and real tables only                              |
| `ink` / `on-ink`            | #0a0a0a / #ffffff | the headline panel, primary button, active chip (dark: white) |
| `on-ink-muted`              | #a3a3a3 (#5c5c5c) | secondary lines on an ink panel (>= 5.6:1)                    |
| `ring`                      | ink               | focus outline (global `:focus-visible`: 2px, 3px offset)      |

Rules: ink inverts with the theme (black panels and buttons in light, white in dark), so the one
emphasis on a screen is always the strongest contrast. Each answer has at most one ink panel (the
award, the current job, UFU, the email); everything else sits on the page or on a `surface` fill.
Surfaces are a fill one tone step from the page, never an outline or a shadow; lines only on form
fields and real tables. Dark surfaces use only the neutral steps #000000, #181818, #272727 and
#313131. Backgrounds are always flat; the one gradient on the site is `text-hero`, a left to right
fade on the letters of a page title (Davi's name, Personal, a post, the 404): #000 to #666 in
light, #fff to #9b9b9b in dark. No italics anywhere (prose `em` is set in weight 500, code
comments are plain muted grey). Never hard-code hex colors in components (the OG template mirrors the
light tokens in `ogColors`). Davi's mark, a calligraphic italic "d", is ink like everything else:
`<BrandMark />` in `currentColor` in the header, the OG cards, and the files from `yarn brand`
(see Brand mark).

**Fonts** (`fonts.ts`): `font-sans` Geist (variable, Latin and Latin Extended) for everything,
kept on purpose: its tight, even grotesque shapes hold up at the oversized display sizes the answers
now use ("2×", "UFU", the award) and stay crisp at 14px; it has tabular figures and full Portuguese
coverage. Headings at 600 with tight negative tracking, body at 400, emphasis at 500, sentence
case. `font-mono` Geist Mono only for literal code. No uppercase labels, no eyebrows above
headings, no letter-spaced captions.

**Type scale** (fluid 360px to 1440px, line-height and tracking included): `text-figure` 72 to
128px (oversized numbers: "2×"), `text-display` 44 to 72px (Personal and 404 h1), `text-name` 40 to
52px (Davi's name in the left pane, the Work h1), `text-title` 34 to 52px (post h1), `text-answer`
32 to 42px (an answer's h1), `text-heading` 22 to 28px (section h2), `text-lead` 18 to 21px,
`text-body` 16 to 17px (set on `body`), `text-small` 14 to 15px (meta lines, chips, tags). The
headline of an ink panel is sized to its container with `fit()` (`answers/parts.tsx`: a `cqi`
size from the text length, clamped, so "Best AI Project in LATAM" and its longer Portuguese title
both fill two lines); put `@container` on an unpadded wrapper, not on the padded panel.

**Layout:** `--container-wide: 80rem` (header, footer and the Work tab), `--container-bento:
64rem` (the Personal tab) and `--container-column: 48rem` (posts, 404), all with a
`clamp(1rem, 4vw, 2.5rem)` gutter (`--gutter`), via `<Container wide? bento?>`.

- Personal: a bento grid of `bg-surface` tiles (`tileClass`: `rounded-panel`, 20 to 24px of
  padding; one gap, 12px, 16px from 640px; fills only). Two columns on a phone: the hello, the
  interests, My teams and Games span both, Spotify and the show sit side by side. Twelve from
  640px: the hello across, Spotify and the interests stacked beside the show, which spans two
  rows. From 1024px the hello takes eight columns and the show stands tall beside it, Spotify and
  the interests under the hello. My teams and Games run across the grid; Writing and Elsewhere
  follow as plain sections. A tile's title is small and muted (`TileTitle`), never an eyebrow;
  rows inside a tile are unfilled and take `surface-strong` on hover. Each My teams card carries a
  faint ASCII animation of its sport, in ink at 30% (see My teams).

- Work, from 1024px: two panes. The left column (20rem, 23rem from `xl`) sticks to the top and
  holds the name, one line, the composer and the chips (they wrap). The canvas on the right shows
  the answer large. The home's canvas is the overview: the award on an ink panel across the top,
  the Azure mark with "3×" Microsoft Certified ("2 Expert, 1 Associate"), the current role, and a contact row.
- Work, below 1024px: the chat-app pattern. The answer fills the page and the composer plus a
  horizontally scrolling chip row are docked to the bottom (`position: fixed`, frosted
  `bg-background/90` + `backdrop-blur`, safe-area aware with `env(safe-area-inset-bottom)` and
  `viewportFit: "cover"`). The dock measures itself into `--dock-h`; `body:has([data-dock])` gets
  that much bottom padding and `scroll-padding-bottom`, so focused elements are never hidden
  under it. On an answer the name steps aside so the question starts at the top. Answers always
  appear above the input, never under it.
- Radii: controls are fully round (chips, buttons, tabs, the composer, the question bubble);
  answer panels and the Personal tiles `rounded-panel` (28px), hovered rows `rounded-surface`
  (20px), logo tiles `rounded-tile` (14px).

**Logos** (`src/lib/logos/`): brand marks from `@iconify-json/logos` (full colour) and
`@iconify-json/simple-icons` (single colour), listed in `registry.ts` (`id`, Iconify `icon`,
`label`, the profile `names` that map to it). `yarn logos` copies only those icons into
`icons.json` (about 30KB, committed), so the multi-MB sets stay dev dependencies. `getLogoSvg()`
builds the SVG on the server and `<BrandLogo>` inlines it: no client JavaScript, no requests.
Colour rule, the same everywhere: a logo keeps its brand colours, except marks whose brand colour
is black or white (GitHub, GitHub Copilot, LangChain, Next.js, Vercel, Instagram's glyph, MCP), which use the simple-icons
version in `currentColor` so they follow the theme. A one-colour mark whose brand colour is neither
takes it from `color` on its entry (PlayStation blue, Valorant red); Steam and Ubisoft stay in
`currentColor`. Logos are decorative next to their name
(`aria-hidden`); a logo standing alone gets `label` (role `img` + `aria-label`). Gradient ids are
scoped per instance (`scopeSvgIds`). Company and school logos are files: set `logo:
"/logos/<name>.svg"` on the entry in `profile.ts` and `<LogoTile>` renders it; without one it shows
a monogram on the tile (Algar, Brain and UFU are monograms until the files are
added; see the `TODO(davi)` notes). Only technologies already in `profile.ts` get a logo. On
an ink panel a tile turns `tone="ink"` (translucent on-ink fill) and the logo keeps its colours.

**Pictures:** the portrait is black and white, its original violet backdrop keyed out, on a
`bg-surface` disc, so it follows the theme like everything else. Certificate prints are cropped to
the certificate (transparent rounded corners), served through next/image (AVIF/WebP, `quality={90}`,
allowed in `next.config.ts` `images.qualities`) and dimmed to 90% brightness in dark mode. No
labels on top of pictures; captions go under them. The album cover on the Spotify card is the one
remote picture: a plain `<img>` straight from Spotify's CDN (the ~300px size it already serves; the
optimizer would only re-encode an ever-changing URL), 10px corners, never cropped, blurred or
covered (Spotify's design guidelines), with the Spotify logo beside it (on a phone, leading the
status line under it). Team logos come from ESPN's CDN (`a.espncdn.com/i/teamlogos/...`, allowed
in `next.config.ts` `images.remotePatterns`) through next/image: Davi's team at 48 to 56px, the
opponent at 20px inline; ESPN's `500-dark` file in dark mode; one that fails falls back to the
light file, then to the team's letters on a disc. The show's poster (TVMaze, or a `/public`
file) stands at 2:3 with 10px corners, never cropped; without one, the title's initials on a dark
tile, like a title card. Valorant's rank emblem comes from `media.valorant-api.com/competitivetiers/`
(also in `remotePatterns`) at 44px; Siege has no emblem source, so its row keeps the game's mark.

**Icons:** Phosphor, regular weight (bold only on the send arrow), imported per icon from
`@phosphor-icons/react/dist/ssr/<Name>` (works in server and client components). Always
`aria-hidden="true"`; the control carries the label.

**Utilities:** `container-column`, `container-wide`, `link-underline` (currentColor underline at
30% that goes solid on hover), `pressable` (scale 0.97 on `:active`) and `pressable-panel` (0.99,
for whole panels), `no-scrollbar` (the docked chip row), `.markdown` (blog prose: no rules or borders;
blockquote as larger text; code blocks on the surface with the ink theme in `src/lib/code-theme.ts`
and dual light/dark CSS variables; each code `figure` is marked `data-ui`).

## Motion

Motion (`motion/react`) in small client leaves, loaded through `LazyMotion` (`domMax`, lazy) with
`strict` (so only `m.*` components) and `MotionConfig reducedMotion="user"`, both in
`src/components/motion/motion-provider.tsx`. Principles (Emil Kowalski): fast, interruptible,
motivated by a state change; ease-out `cubic-bezier(0.23, 1, 0.32, 1)` for arrivals, never animate
from `scale(0)`, transform and opacity only.

| What                                   | Where                                      | Timing                                                                                                                                            |
| -------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |

The canvas swap is the assistant's signature: a chip click lights its chip at once (optimistic),
the answer on screen steps back, and when the new route has rendered `Canvas` composes it in
front of the visitor in its `--p` order (bubble, title, then the pictures). Motion runs it on the
compositor (opacity, transform, filter); a new swap stops the one in flight, and the inline styles
are removed afterwards (a lingering `filter` would make every panel a containing block).

The certificate viewer is the other picture moment: the print lifts off the page (it hides and
the large copy starts at exactly its rect, then grows to the centre), the page fades to the
surface tone behind it, and Escape, a click anywhere or the close button run it back into its
slot. It is a native modal `<dialog>` (focus moves to Close and returns to the print; the page is
inert), and while it is open `html` stops scrolling and keeps the classic scrollbar's width as
padding (`--scrollbar-gap`), so nothing shifts. Without JavaScript the print's link opens the PNG.

Not animated on purpose: typing and the live match (instant), the locale switch. The CSS
entrances only play on a full load: `data-nav` is set on `<html>` at the first in-site navigation,
and from then on the canvas runs the Motion version. Reduced motion: every hidden starting state
lives inside `prefers-reduced-motion: no-preference`, the canvas swap only fades (200ms), `Reveal`
returns early, Motion skips transforms and the team cards' ASCII animations hold one still frame.

## Brand mark

Davi's logo is a calligraphic italic "d": an elliptical bowl tilted about 30°, its right side
rising into the stem, which ends in a flag pointing back left. It was traced from his 1254px PNG
(potrace, then curves merged and refitted to the PNG's sub-pixel outline: 15 cubic curves, within
1.5px of the original at 1254px) and lives in one place, `src/components/brand/mark.ts`:

- `glyph`: the filled outline and the bowl's counter (`fill-rule="evenodd"`), viewBox `0 0 961 839`
  with 9 units of air on every side;
- `pen`, `penWidth`, `penLength`: the glyph's centre line in writing order, a 160-unit round-capped
  stroke that covers every pixel of the glyph (the farthest is 76 units away).

**Draw-on.** `<BrandMark draw>` (the header) renders an inline script before the SVG and masks
the glyph with a white rect plus the pen. On the first page load of a session (sessionStorage
`brand-drawn`), unless reduced motion is preferred, the script sets `data-brand-draw` on `<html>`
before the mark is painted; the CSS then hides the rect and slides the pen's dash in (900ms), so
the "d" is written bowl first, then the stem and the flag, ending exactly on the filled glyph; on
`animationend` the attribute goes. Without JavaScript, on reloads, client navigations (the header
stays mounted) and with reduced motion it is just the glyph. On hover of the home link the mark
straightens a little and lifts (200ms ease-out, pointer devices only).

## Spotify now playing

The first of the Personal tab's live elements (the others are My teams and Games): a tile of the
bento grid with what Davi is listening to on Spotify (the cover, the song, the artists, and a
small equalizer while it plays) or the last song played, linking to the track. It sits under the
hello, beside the Watching tile on a phone and beside the interests from 1024px.

- **Server:** `src/lib/spotify/now-playing.ts` exchanges `SPOTIFY_REFRESH_TOKEN` (with
  `SPOTIFY_CLIENT_ID` and `SPOTIFY_CLIENT_SECRET`) for an access token at
  `accounts.spotify.com/api/token` (kept in memory until a minute before it expires), asks
  `GET /v1/me/player/currently-playing` and, when nothing is playing (204), a podcast or an ad
  is, falls back to the paused song or `GET /v1/me/player/recently-played?limit=1`. It returns
  `status` `"playing"` or `"recent"` with `title`, `artists[]`, `album`, `albumArt`, `url` (and
  `progressMs`, `durationMs` while playing), `"offline"` on any failure (logged without secrets)
  or `"unconfigured"` without the env vars. `src/app/api/now-playing/route.ts` serves it
  with `Cache-Control: public, s-maxage=30, stale-while-revalidate=60` and `X-Robots-Tag: noindex`,
  always 200, so builds and previews never depend on Spotify.
- **Client:** `NowPlayingCard` fetches it on mount and every 30 seconds while the tab is visible
  (a `visibilitychange` listener stops it when hidden and catches up on return; no scroll
  listeners). The tile keeps its size in every state (at least 13rem tall, the grid row decides
  the rest), so nothing shifts: a skeleton, the song, or, for `offline` and `unconfigured`, a
  deliberate profile tile: the Spotify mark large on a page-tone square, "On Spotify", the handle
  and "Listen on Spotify" (a pill from 640px), linking to the profile (also what renders without
  JavaScript, via the `noscript:` variant). A song change is announced in a polite live region
  (not the first one). The Spotify logo (`logo`, 16 to 24px) and mark (`mark`, 40px) come from the
  server as props, so the logo registry stays out of the client bundle.
- **Not machine-readable on purpose:** the song is ephemeral, so it is not in the Markdown,
  llms.txt, MCP, search or OpenAPI. The Spotify profile is a regular social (Elsewhere, Markdown,
  JSON, `sameAs`).
- **Setup:** README, "Spotify now playing" (`yarn spotify:token`, `.env.example`).

Beside it, the **Watching** tile: the first show in `watching` (`personal.ts`), static, linking to
a page about it. It is the grid's tall tile (two rows from 640px; beside the hello from 1024px):
the poster on top (two thirds of the tile's width on a phone, 12rem from 640px, the full width
from 1024px), then "Watching", the title (up to three lines) and the network and year. The poster
comes from TVMaze (`api.tvmaze.com/singlesearch/shows?q=<title>`, no key, `revalidate` one day,
4s timeout, the `original` image, only `static.tvmaze.com`); a `poster` file in `/public` wins,
and any failure falls back to the title's initials. It is a static fact, so the Markdown and
llms-full carry it.

## My teams (ESPN)

The My teams tile of the Personal tab runs across the grid with one card per team in
`personal.ts` (Brooklyn Nets, Corinthians, Minnesota Vikings): stacked on a phone, a row each
from 640px (the team on the left, the game on the right), three across from 1024px. Each card is
told from Davi's side, so it is clear which team is his and how it went:

1. His team leads: its logo large (48 to 56px), its name, the competition under it.
2. The state: "Live" with the pulsing dot and the clock, "Final, yesterday", or "Next game".
3. The result in words, with the higher score first: "Lost 136 to 109", "Won 27 to 24",
   "Draw, 1 to 1"; live, "Leading 14 to 10", "Trailing 88 to 84", "Tied 0 to 0"; for a game to
   come, its day and time. In Portuguese: "Perdeu de 136 a 109", "Ganhou de 2 a 1",
   "Empatou em 1 a 1", "Ganhando de...", "Perdendo de...".
4. The opponent, small, with its logo and where the game is: "vs Pacers" at home, "at Lions"
   away; in Portuguese the phrase follows the result, "para o Pacers, em casa", "do Palmeiras,
   fora de casa", "com o...", "contra o...", with the article from `articles()` in
   `src/lib/teams/types.ts` ("a Chapecoense", "da Ponte Preta"; add a feminine club there).

A card with a game links to it on espn.com; its accessible name is the whole sentence ("Brooklyn
Nets, Lost 136 to 109 vs Indiana Pacers. NBA, Final, yesterday").

- **Source:** ESPN's public site API (`site.api.espn.com/apis/site/v2/sports/...`), keyless and
  undocumented. `src/lib/teams/espn.ts` reads each team's schedule (the three teams in parallel):
  NBA and NFL with the default, regular season (`seasontype=2`) and postseason (`seasontype=3`);
  soccer through `soccer/all/teams/{id}/schedule` (every competition ESPN has for the club:
  Brasileirão, Copa do Brasil, Libertadores...) and the league path, each also with
  `fixture=true` for the games to come. A schedule's status lags, so the latest game that has
  started is re-read from that day's scoreboard (`dates=YYYYMMDD`, the US Eastern day ESPN groups
  by). The card shows a live game; else a final from the last 36h (NBA), 48h (soccer) or 72h
  (NFL), unless the next game starts within 3h; else the next game; else the last result; else
  nothing. Parsing is defensive (every field optional; scores as strings, numbers or objects;
  logos only from `a.espncdn.com/i/`; our side found by team id), and a team ESPN cannot answer
  for comes back with `game: null` without failing the others. Errors are logged as messages.
- **Caching:** upstream through the Data Cache (`next.revalidate`): schedules 10 minutes, a
  scoreboard 15 seconds around a game and an hour once it has settled. `/api/teams` is always 200,
  with `s-maxage` 30s while a game is live, 60s near a start, a fresh result or after a failure,
  600s otherwise (`teamsMaxAge`), and `stale-while-revalidate` twice that.
- **Client:** `TeamsBoard` asks once on mount; then every minute only while a game is live (or its
  start has come) and the tab is visible, and once at the start of a game due within six hours.
  Hidden tabs stop and catch up on return. Every state has the same size: a skeleton; live (the
  pulsing dot, "Live", the quarter and clock or the minute, "Leading..."); final (with the day,
  "Won..."); the next game (day and time in the viewer's time zone, in the page's language); and
  unavailable (the team and "No game data right now"). Without JavaScript: the teams and that
  line. A game going live or ending is announced in a polite live region (never on the first
  answer).
- **Mocks:** `?mock=live | final | upcoming | mixed | unavailable` on the page (forwarded to the
  route by `liveUrl()`) answers from `src/lib/teams/fixtures.ts`, run through the real parser, in
  `yarn dev` or a production server started with `PERSONAL_MOCKS=1` (`src/lib/mock.ts`). The live
  site ignores it. Fixtures are API-shaped, including a schedule lagging behind the scoreboard.
- **Not machine-readable on purpose:** scores are ephemeral. The Markdown and llms-full list the
  teams and their leagues only.
- **Change the teams:** edit `teams` in `src/content/personal.ts` (README, "My teams").

**Animations.** Behind each card's content runs an ASCII animation of its sport, picked by `ascii`
on the team, calm by default and livelier while the card is hovered, focused from the keyboard or
for 1.6s after a tap:

- `basketball` (Nets): a hoop at the right (backboard, rim, a net of crossed strands `\/\/`) and a
  ball dribbling slowly beside it, lit from the upper left, its seams turning. Lively: a jump shot
  from the top of a dribble, the swish (the net jumps, sways and stretches), a bounce and the
  dribble back, with a fading trail.
- `soccer` (Corinthians): a goal at the top right, its net a lattice (`|`, `-`, `+`), a stand of
  heads (`o`) behind it, a ball at the bottom right rolling to and fro with its pentagons turning.
  Calm, a wave runs along the stand, arms up as it passes (`\o/`). Lively: a free kick curls into
  the top corner, smaller as it goes deeper; the net bulges, the stand jumps; a new ball rolls in.
- `longship` (Vikings): a longship sailing left with a striped square sail, round shields
  (`o o o`), oars and a dragon prow, rocking on swells drawn as tildes (`~`) under the whole card.
  Lively: the sea rises, the oars pull, the sail fills and the horn sounds, arcs (`( ( (`) opening
  ahead of the prow.

How (`src/lib/ascii`): a scene (`scenes/*.ts`: `step`, `draw`, `still`) draws strokes, discs, lit
spheres and chosen glyphs into a field of character cells (`field.ts`), in card units (the
card's height is 1), composed from the right edge, where a card has the least text, and fading out
towards the left (nothing past about 1.6 card heights from the right edge), so the picture sits
beside the words, never on them. `renderer.ts` turns each cell's ink into a glyph of the ramp
` .:-=+*#%@` (or a chosen one: `o ~ / \ | ( )`), stamped from an atlas drawn once in Geist Mono at
the screen's density (up to 2x) on a pixel-aligned grid, cells about a 24th of the card's height
(7.5 to 10px); on every tick a few cells step a glyph up or down (the shimmer, more when lively).
`backdrop.ts` runs it on one shared requestAnimationFrame loop (`ticker.ts`): 12fps calm, up to
20fps lively, only while the canvas is on screen (IntersectionObserver) and the tab is visible;
sized by a ResizeObserver; recoloured when the theme class on `<html>` changes. With reduced
motion each scene shows one still frame (the shot in flight, the ball curling in, the horn
sounding). The canvas is `absolute inset-0 -z-10` in the card (`relative isolate overflow-hidden`,
so it stays under the text and inside the corners), decorative (`aria-hidden`, no pointer events),
in `text-foreground` at 30% opacity, 50% while lively; it fills the box the content already sized,
so nothing shifts. A new scene: a file in `scenes/`, its name in `AsciiScene` (`types.ts`) and in
`scenes/index.ts`.

## Games (trackers, Steam and profiles)

The Games tile runs across the grid under My teams: Valorant and Rainbow Six Siege with their
rank and stats, then the Steam card and PlayStation, two across from 640px, each with its brand
mark from the logo registry.

- **Valorant and Siege** (`src/lib/trackers/`): Tracker.gg has no website embed (its overlays are
  for OBS) and its developer API does not cover these games, and Riot's and Ubisoft's own APIs are
  closed to a personal site, so each comes from a keyed community API that reads the official
  data. Nothing is scraped.
  - Valorant, `HENRIK_API_KEY` (HenrikDev, `api.henrikdev.xyz`, header `Authorization`):
    `GET /valorant/v3/mmr/{region}/{platform}/{name}/{tag}` (the rank, RR; required; 10 minutes),
    `/valorant/v1/stored-matches/{region}/{name}/{tag}?mode=competitive` (the last 20
    competitive matches: K/D and win rate; 30 minutes) and `/valorant/v2/account/{name}/{tag}`
    (the level; 6 hours). Without the matches the win rate comes from the act's games. The rank
    emblem is valorant-api.com's `competitivetiers` image for the tier.
  - Siege, `R6DATA_API_KEY` (R6Data by Arenyze, `public-api.arenyze.com/r6/api`, header
    `api-key`): `GET /v2/profile?nameOnPlatform=...&platformType=uplay` (30 minutes): the level
    and Ubisoft's ranked board for the latest season (rank, RP, kills and deaths, wins, losses
    and abandons).
  - `getTrackers()` asks both in parallel (6s timeouts, through the Data Cache) and answers per
    game `ok` (`rank` `{ tier, division, icon }`, `points` RR or RP, `kd`, `winRate`, `level`,
    `scope`: the last N matches or this season), `offline` (logged without the URL or key) or
    `unconfigured`. `/api/trackers`: `s-maxage=600, stale-while-revalidate=3600`, always 200.
  - `TrackerCards` asks once on mount. A game whose key is set (`trackersConfigured()`, read on
    the server at build) holds a skeleton of its stats from the first paint, so nothing moves;
    then the rank (the emblem in the tile, else the game's logo), the points, three figures (K/D,
    win rate, level) and what they cover ("Last 20 competitive matches", "This season"). Without
    the key, while offline and without JavaScript, the row is the Tracker.gg link it always was.
    The whole row links to Tracker.gg in every state. Mocks (`src/lib/trackers/fixtures.ts`, API-shaped,
    through the real parsers): `?mock=ranked`, and any team or Steam scenario, shows ranked
    stats; `offline` and `unavailable` show the links.

- **Steam** (`src/lib/steam/steam.ts`): with `STEAM_API_KEY`, the vanity name becomes a SteamID64
  (`ResolveVanityURL`, cached a day and in memory; `STEAM_ID` skips it), then
  `GetPlayerSummaries` (30s), `GetRecentlyPlayedGames` (5 minutes) and `GetOwnedGames` (a day) in
  parallel; only the summary is required. It answers `ok` (`online`, `playing`, the top three
  `recent` games by minutes in the last two weeks, `gameCount`), `offline` on any failure (logged
  without the key) or `unconfigured`. `/api/steam`: `s-maxage=60, stale-while-revalidate=120`,
  always 200. `SteamCard` asks every minute while the tab is visible (the `NowPlayingCard`
  pattern): "Playing now" with the live dot, else the most played game of the last two weeks and
  its time, else "On Steam" with the handle and the size of the library. Unconfigured, offline
  and no-JS show the profile link. Steam only answers for a public profile with public game
  details. Mocks: `?mock=playing | recent | idle | offline` (the teams' scenarios map onto them).
- **PSN:** a link card to PSNProfiles. PlayStation has no public API; nothing is scraped.
- Not in `socials` or `sameAs`: they are game handles, not identity profiles. Presence, ranks
  and stats are ephemeral and stay out of the machine-readable layer; the Markdown and llms-full list the
  profiles under "Games".

## Page conventions

```tsx
type PageProps = { params: Promise<{ lang: string }> };

export async function generateMetadata({
  params,
}: PageProps): Promise<Metadata> {
  const { lang } = await params;
  if (!isLocale(lang)) return {};
  const dict = getDictionary(lang);
  return buildMetadata({
    lang,
    path: "/personal",
    title: dict.meta.personal.title,
    description: dict.meta.personal.description,
  });
}

export default async function Page({ params }: PageProps) {
  const { lang } = await params;
  if (!isLocale(lang)) notFound();
  const dict = getDictionary(lang);
  return <>{/* sections */}</>;
}
```

- The layout already renders `<main id="main">`, header and footer. Pages render a `<Container>`
  with sections, exactly **one `<h1>`**, section titles as `<h2 className="text-heading">`.
- All UI copy from the dictionary, all facts from `profile`, all internal URLs from `routes`.
- Semantic HTML: `<section>`, `<article>`, `<time dateTime>`, lists for lists; label icon-only links.
- Keep pages static (no `headers()`/`cookies()`); client JS only in the small leaves listed above.
- No dashes or middle dots in visible text: commas, "to" in ranges, spacing between items.

- `/_vercel/insights/script.js` 404s locally (Vercel Analytics only exists on Vercel).
- Metadata image routes inside a route group get a hashed segment: a Work answer's card is

  from a parent segment.

  renderer draws nothing for WebP); those files are listed in `outputFileTracingIncludes`.

  portfolio without photography), `covered-text` (the docked composer covers the page as it
  scrolls, which is the point), `edge-text` (the docked chip row scrolls sideways), `body-size`
  (the answers carry little running text; paragraphs stay at 16 to 17px).
- For dynamic `notFound()` (unknown slug, `/en/foo`) Next 16 streams the 404 UI via the RSC payload
  (status 404 + `noindex`); the HTML shell itself is minimal. Known static pages are fully prerendered.

### Proxy (`src/proxy.ts`)

1. `*.md` -> rewrite to `/markdown/...` (unknown page: 404).
2. `/{lang}/ask?q=...` (the composer without JS): 303 to the matched `/{lang}/work/<topic>`; no
   match falls through to the static "no written answer" page.
3. `/{lang}/...`: if `Accept` explicitly prefers `text/markdown` (q above zero and at least the
   HTML q; `*/*` never counts) and the path is a known page, rewrite to its Markdown with
   `Vary: Accept`. Otherwise pass through with the `Link` header.
4. Wrong-cased prefix -> 308 to the canonical one.
5. Anything else -> 307 to the negotiated locale (cookie, then `Accept-Language`) with
   `Vary: Accept, Accept-Language, Cookie`. `/` asking for Markdown gets the negotiated Work
   Markdown directly (plus `Content-Location`), and the `/` redirect carries the site-level `Link`s.

The matcher skips `_next`, `api`, `mcp`, paths with a dot (except `.md`) and metadata image routes.

### Changing things

- Facts: edit `profile.ts`; Markdown, JSON, JSON Resume, llms files, MCP, search and OG update.
- Posts: add the Markdown file; sitemap, llms, `posts.json`, MCP (`list_posts`, resources),
  search and the post OG image pick it up at build time.
- A new page: add it to `PageRef`/`parsePagePath`/`pagePath` in `discovery.ts`, a renderer in
  `markdown.ts`, a route under `src/app/markdown/`, and an entry in `sitemap.ts`.
- The skill: edit `skillMarkdown()` in `well-known.ts`; the index digest is computed from it.
- MCP: tools are declared in `mcp.ts` (`toolInputs`, `toolMeta`); the server card reads the same
  declarations. The route serves 2026-07-28 clients through `createMcpHandler` and 2025-era
  clients (`initialize` handshake) through a stateless transport with JSON responses, so plain
  JSON-RPC POSTs work.

### Checks that do not apply (on purpose)

- **OAuth / OIDC discovery, OAuth Protected Resource (RFC 9728), Auth.md**: everything is public
  and read-only with no authentication. Publishing these would advertise auth that does not exist.
- **Web Bot Auth** (`/.well-known/http-message-signatures-directory`): for operators of bots that
  sign their requests. This site sends no bot traffic (the scanner marks it informational).
- **A2A agent card** (`/.well-known/agent-card.json`): there is no conversational agent to
  delegate to; MCP, OpenAPI and the skill cover tool and data access.
- **Commerce** (x402, MPP, UCP, ACP): nothing is for sale; the scanner scores these only for shops.
- **DNS-AID**: SVCB records under `_agents.davilacerda.com`, signed with DNSSEC. This is DNS
  configuration, not code; add it at the DNS provider if wanted.

### Known limitations

- `next start` replaces the `Vary` header of prerendered HTML (both from the proxy and from
  `next.config` `headers()`), so the HTML variant does not show `Vary: Accept` locally; the
  Markdown variant does. On Vercel the proxy runs before the CDN cache and each variant is cached
  under its own rewritten route, so they never mix there. A third-party cache in front of the
  site could still serve cached HTML to a Markdown request; the `.md` URLs avoid that entirely.
- `.md` and JSON renditions are not `noindex`; they send `Link: <html>; rel="canonical"` instead.
- The RSS URLs advertised in Link headers and llms.txt (`/{lang}/personal/blog/rss.xml`) come
  from the blog work.
